2. WPF FUNDAMENTALS & CONCEPTS
================================================================================

2.1 WHAT IS WPF?
----------------
Windows Presentation Foundation (WPF) is a UI framework for building Windows
desktop applications with rich user interfaces.

Key Features:
- XAML-based UI definition (declarative markup)
- Data binding (connect UI to data automatically)
- Styling and templating (customize appearance)
- Vector graphics (resolution-independent)
- Animation support
- Hardware acceleration

2.2 XAML (eXtensible Application Markup Language)
--------------------------------------------------
XAML is an XML-based language used to define UI elements in WPF.

Example:
    <Button Content="Click Me"
            Command="{Binding ClickCommand}"
            Width="100"
            Height="30"/>

Key Concepts:
- Elements: UI controls (Button, TextBox, Grid, etc.)
- Attributes: Properties of elements (Width, Height, Content, etc.)
- Binding: {Binding PropertyName} connects UI to data
- Resources: Reusable styles, templates, and objects
- Triggers: Automatic UI changes based on conditions

2.3 DATA BINDING
----------------
Data Binding connects UI elements to data sources automatically.

Types:
1. One-Way Binding: Data flows from source to UI (read-only)
   Example: Text="{Binding UserName}"

2. Two-Way Binding: Data flows both ways (read/write)
   Example: Text="{Binding UserName, Mode=TwoWay}"

3. One-Time Binding: Data loads once at startup
   Example: Text="{Binding StartupMessage, Mode=OneTime}"

Binding Syntax:
    {Binding Path=PropertyName,
             Mode=TwoWay,
             UpdateSourceTrigger=PropertyChanged}

2.4 DEPENDENCY PROPERTIES
--------------------------
Special properties that support:
- Data binding
- Styling
- Animation
- Property value inheritance

Example:
    public static readonly DependencyProperty MyProperty =
        DependencyProperty.Register("MyProperty", ...);

2.5 COMMANDS
------------
Commands implement the ICommand interface for handling user actions.

Benefits:
- Separates UI logic from business logic
- Enables/disables controls automatically
- Works with any input (mouse, keyboard, touch)

Example:
    <Button Command="{Binding SaveCommand}" Content="Save"/>

In ViewModel:
    public ICommand SaveCommand { get; private set; }
    SaveCommand = new RelayCommand(ExecuteSave, CanExecuteSave);

2.6 CONVERTERS
--------------
Convert data between different types for display.

Example: BooleanToVisibilityConverter
    <TextBlock Visibility="{Binding IsVisible,
                           Converter={StaticResource BoolToVisConverter}}"/>

3. MVVM ARCHITECTURE PATTERN
================================================================================

3.1 WHAT IS MVVM?
-----------------
Model-View-ViewModel is a design pattern that separates:
- User Interface (View)
- Business Logic (ViewModel)
- Data (Model)

Benefits:
- Testable code (ViewModels can be unit tested)
- Maintainable (clear separation of concerns)
- Reusable (ViewModels can work with multiple Views)
- Designer-friendly (designers work on Views, developers on ViewModels)

3.2 THE THREE LAYERS
--------------------

┌─────────────────────────────────────────────────┐
│                     VIEW                        │
│  (XAML + Code-behind)                          │
│  - User Interface                               │
│  - Visual appearance                            │
│  - No business logic                            │
└─────────────────────────────────────────────────┘
                      ↕ Data Binding
┌─────────────────────────────────────────────────┐
│                  VIEWMODEL                      │
│  (C# Class)                                     │
│  - Properties (bound to View)                   │
│  - Commands (user actions)                      │
│  - Business logic                               │
│  - State management                             │
└─────────────────────────────────────────────────┘
                      ↕ Method Calls
┌─────────────────────────────────────────────────┐
│                    MODEL                        │
│  (Data Classes, Services)                       │
│  - Data structures                              │
│  - Database access                              │
│  - API calls                                    │
│  - Domain logic                                 │
└─────────────────────────────────────────────────┘

3.3 DATA FLOW EXAMPLE
---------------------

User clicks "Save" button
    ↓
View executes SaveCommand (binding)
    ↓
ViewModel's ExecuteSave method runs
    ↓
ViewModel calls Service to save data
    ↓
Service updates Model/Database
    ↓
ViewModel raises PropertyChanged event
    ↓
View updates automatically via binding

3.4 INOTIFYPROPERTYCHANGED INTERFACE
-------------------------------------
Critical interface for MVVM - notifies UI when data changes.

Implementation:
    public class MyViewModel : INotifyPropertyChanged
    {
        public event PropertyChangedEventHandler PropertyChanged;

        protected void OnPropertyChanged(string propertyName)
        {
            PropertyChanged?.Invoke(this,
                new PropertyChangedEventArgs(propertyName));
        }

        private string _name;
        public string Name
        {
            get => _name;
            set
            {
                _name = value;
                OnPropertyChanged(nameof(Name)); // Notify UI!
            }
        }
    }

5.1 BaseViewModel.cs
--------------------
PURPOSE: Base class for all ViewModels providing common functionality

KEY FEATURES:
- Implements INotifyPropertyChanged
- Provides SetProperty method for property change notification
- Reduces boilerplate code

USAGE:
    All ViewModels inherit from this class

CODE PATTERN:
    public class MyViewModel : BaseViewModel
    {
        private string _myProperty;
        public string MyProperty
        {
            get => _myProperty;
            set => SetProperty(ref _myProperty, value);
        }
    }

WHY IT EXISTS:
    Avoids repeating INotifyPropertyChanged implementation in every ViewModel

--------------------------------------------------------------------------------

5.2 MainWindowViewModel.cs
---------------------------
PURPOSE: Orchestrates the entire application workflow

KEY RESPONSIBILITIES:
- Manages all child ViewModels (creates and holds references)
- Handles configuration save/load
- Executes training workflow
- Coordinates between different tabs/views
- Manages global application state

KEY PROPERTIES:
- GeneralSettings        : GeneralSettingsViewModel
- DatabaseSettings       : DatabaseSettingsViewModel
- InputFields            : InputFieldsViewModel
- DataProcessing         : DataProcessingPipelineViewModel
- FeatureEngineering     : FeatureEngineeringViewModel
- DataBalancing          : DataBalancingViewModel
- TrainingParameters     : TrainingParametersViewModel
- ExploratoryDataAnalysis: ExploratoryDataAnalysisViewModel
- TrainingLogs           : TrainingLogsViewModel

KEY COMMANDS:
- SaveConfigurationCommand   : Saves current config to JSON
- LoadConfigurationCommand   : Loads config from JSON file
- StartTrainingCommand       : Initiates ML training workflow
- OpenDatabaseExplorerCommand: Opens database browser window

METHODS:
- ExecuteStartTraining(): Main training orchestration method
  1. Validates configuration
  2. Loads data from database
  3. Processes data (cleaning, transformations)
  4. Trains model (AutoML or Traditional)
  5. Evaluates and saves model

DATA FLOW:
    User clicks "Start Training"
      ↓
    StartTrainingCommand executes
      ↓
    Collects config from all child ViewModels
      ↓
    Passes config to ML.NET training logic
      ↓
    Updates TrainingLogs in real-time
      ↓
    Shows completion dialog

WHY IT EXISTS:
    Central coordinator - "brain" of the application

5.6 DataProcessingPipelineViewModel.cs
---------------------------------------
PURPOSE: Configures data preprocessing steps

KEY PROPERTIES:
- DropMissingValues    : Remove rows with nulls?
- ImputeMissingValues  : Fill nulls with values?
- NormalizeFeatures    : Scale numeric features?
- RemoveDuplicates     : Delete duplicate rows?

PREPROCESSING STEPS CONFIGURED:
1. Missing Value Handling
   - Drop rows with any nulls
   - OR Impute (mean/median/mode)

2. Feature Scaling
   - Min-Max normalization (0-1 range)
   - Z-score standardization (mean=0, std=1)

3. Data Cleaning
   - Remove duplicates
   - Remove outliers (optional)

WHY IT EXISTS:
    Raw data often needs cleaning before training

--------------------------------------------------------------------------------

5.7 FeatureEngineeringViewModel.cs
-----------------------------------
PURPOSE: Creates new features from existing ones

KEY FEATURES:
- Create polynomial features (x², x³, etc.)
- Create interaction features (x₁ × x₂)
- Binning (convert continuous to categorical)
- Date/time feature extraction

EXAMPLE TRANSFORMATIONS:
    Age → AgeGroup (bins: 0-18, 19-65, 65+)
    Date → DayOfWeek, Month, Quarter
    Price, Quantity → TotalCost (Price × Quantity)

WHY IT EXISTS:
    Feature engineering often improves model accuracy significantly

--------------------------------------------------------------------------------

5.8 DataBalancingViewModel.cs
------------------------------
PURPOSE: Handles class imbalance in classification problems

PROBLEM:
    If dataset has 95% Class A and 5% Class B, model may ignore Class B

SOLUTIONS OFFERED:
1. Oversampling minority class (SMOTE)
2. Undersampling majority class
3. Class weights adjustment

KEY PROPERTIES:
- ApplyBalancing      : Enable/disable balancing
- BalancingMethod     : SMOTE, Undersample, etc.
- TargetRatio         : Desired class distribution

WHY IT EXISTS:
    Imbalanced datasets produce biased models

--------------------------------------------------------------------------------

5.9 TrainingParametersViewModel.cs
-----------------------------------
PURPOSE: Configures ML training settings

KEY PROPERTIES:
- ModelType              : Binary/Multiclass Classification or Regression
- TargetField            : Column to predict
- UseAutoML              : AutoML vs. Traditional training
- TestFraction           : Train/test split ratio (e.g., 0.2 = 80/20)

TRADITIONAL TRAINING SETTINGS:
- SelectedAlgorithm      : Algorithm to use (FastTree, LGBM, etc.)
- Parameters             : Algorithm-specific hyperparameters
  Example: NumberOfTrees=100, LearningRate=0.1

AUTOML SETTINGS:
- MaxExperimentTimeInSeconds : Time budget for AutoML
- MaxModelsToTry            : Number of algorithms to try
- OptimizingMetric          : Accuracy, AUC, F1Score, etc.
- UseCrossValidation        : k-fold validation
- NumberOfFolds             : k value (typically 5)
- AutoMLSeed                : Random seed for reproducibility

KEY COMMANDS:
- AddParameterCommand    : Add custom hyperparameter
- RemoveParameterCommand : Delete parameter

ALGORITHM SELECTION:
    Model Type              Available Algorithms
    ────────────────────────────────────────────
    Binary Classification   FastTree, LGBM, SDCA, ...
    Multiclass             OVA, LGBM, FastTree, ...
    Regression             FastTree, SDCA, LGBM, ...

WHY IT EXISTS:
    Training configuration is complex - needs dedicated UI

- OutlierCount       : Number of outliers found
- OutlierPercentage  : % of dataset
- OutliersList       : Specific outlier values

KEY COMMANDS:
- DetectOutliersCommand  : Run detection
- RemoveOutliersCommand  : Clean dataset

WHY IT EXISTS:
    Outliers can skew models - need identification and handling

7.3 DatabaseAnalyticsService.cs
--------------------------------
PURPOSE: Database-side data analysis (statistics, summaries)

KEY METHODS:
    Task<DatasetSummary> GetDatasetSummaryAsync(connectionString,
                                                tableName,
                                                columns,
                                                whereClause)

    Task<List<ColumnStatistics>> GetColumnStatisticsAsync(...)

    Task<List<MissingValueInfo>> GetMissingValuesAnalysisAsync(...)

    Task<BoxPlotData> GetBoxPlotDataAsync(connectionString,
                                         tableName,
                                         columnName,
                                         whereClause)

STATISTICS COMPUTED (SQL-side):
    - Row count
    - Min, Max, Mean, Median
    - Standard deviation
    - Quartiles (Q1, Q2, Q3)
    - Missing value count and percentage
    - Outliers (IQR method)

EXAMPLE SQL QUERY:
    SELECT
        COUNT(*) as RowCount,
        AVG(CAST(ColumnName AS FLOAT)) as Mean,
        STDEV(CAST(ColumnName AS FLOAT)) as StdDev,
        MIN(ColumnName) as Min,
        MAX(ColumnName) as Max,
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY ColumnName) as Q1,
        PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY ColumnName) as Median,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY ColumnName) as Q3
    FROM TableName
    WHERE WhereClause

WHY DATABASE-SIDE?
    - Millions of rows - loading to memory is slow
    - SQL Server optimized for aggregations
    - Faster than client-side computation

WHY IT EXISTS:
    EDA needs statistics - compute efficiently server-side

11.2 COMMAND PATTERN
--------------------
Encapsulates actions as objects

    public interface ICommand
    {
        bool CanExecute(object parameter);
        void Execute(object parameter);
        event EventHandler CanExecuteChanged;
    }

IMPLEMENTATION (RelayCommand):
    public class RelayCommand : ICommand
    {
        private readonly Action<object> _execute;
        private readonly Func<object, bool> _canExecute;

        public RelayCommand(Action<object> execute,
                           Func<object, bool> canExecute = null)
        {
            _execute = execute;
            _canExecute = canExecute;
        }

        public bool CanExecute(object parameter)
        {
            return _canExecute == null || _canExecute(parameter);
        }

        public void Execute(object parameter)
        {
            _execute(parameter);
        }

        public event EventHandler CanExecuteChanged
        {
            add { CommandManager.RequerySuggested += value; }
            remove { CommandManager.RequerySuggested -= value; }
        }
    }

12. TROUBLESHOOTING GUIDE
================================================================================

12.1 COMMON ISSUES
------------------

ISSUE: UI not updating when property changes
CAUSE: PropertyChanged event not raised
FIX: Ensure OnPropertyChanged(nameof(Property)) is called
     OR Use SetProperty() method from BaseViewModel

ISSUE: Command button always disabled
CAUSE: CanExecute returns false
FIX: Check CanExecute logic
     Call CommandManager.InvalidateRequerySuggested() to refresh

ISSUE: Binding not working
CAUSE: DataContext not set or wrong property name
FIX: Set View's DataContext to ViewModel
     Check property name spelling in binding

ISSUE: Collection changes not reflected in UI
CAUSE: Using List<T> instead of ObservableCollection<T>
FIX: Change to ObservableCollection<T>

ISSUE: Async deadlock
CAUSE: Calling .Result or .Wait() on async method
FIX: Use await everywhere
     Use ConfigureAwait(false) in library code

12.2 DEBUGGING TIPS
-------------------

1. Check Output Window for binding errors
2. Use Snoop or WPF Inspector for live visual tree
3. Set breakpoints in property setters
4. Log PropertyChanged events
5. Verify DataContext hierarchy
